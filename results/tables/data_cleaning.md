**Deduplication key** (`src.data.dedup_key`, used by every decision): the sorted multiset of normalized tokens. Tokens come from `norm_key`: Unicode NFC, lowercased, every punctuation character (Unicode category P, incl. the Bangla danda) replaced by a space, whitespace collapsed. Sorting makes the key word-order-insensitive, because all three handcrafted feature families are (docs/PROTOCOL.md §3.3). The "exact key" column re-runs the same step on the same input with the exact string (whitespace collapsed only); it is reported for comparison only and decides nothing.

Steps 2-4 are applied at row level to the union of problems found in either language (R9), so `bnintent30-en` and `bnintent30-bn` share one cleaned row set. Steps 3 and 4 are greedy in a fixed order (step 3: test, val, train, then uid; step 4: uid), and a row is dropped only for colliding with a row that is *kept*.

- **Cost of R9 on the English test set:** using English text alone, step 4 would remove 4 test rows. The BNIntent30 step-4 test removals are triggered by the Bangla side; because both tracks must hold identical rows (R9), the paired English rows go too, although their English texts are distinct. So the English test set loses distinct items to keep the comparison parallel.
